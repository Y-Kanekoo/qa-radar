# 🔬 Web Learning Lab

> **動いているWebアプリを透視(X-Ray)して、仕組みをまるごと理解する**教材アプリ。

TODOアプリを操作すると、その裏側で起きたこと —
実際のHTTPリクエスト/レスポンス、サーバー内部の処理ステップ、実行されたSQL —
がすべてリアルタイムで可視化されます。表示されるのは演出ではなく**全部実測値**です。

📐 設計の全体像・意思決定の理由は **[DESIGN.md](DESIGN.md)** にまとまっています(先に読むのがおすすめ)。

## 起動方法

Python 3.11 以上だけあれば動きます。**インストール作業は一切不要**(標準ライブラリのみ)。

```bash
cd learning-lab
python3 server.py            # → ブラウザで http://localhost:8000 を開く
python3 server.py 8080       # ポートを変えたいとき
```

停止は `Ctrl+C`。データは `data/todos.db`(SQLiteファイル)に保存され、再起動しても残ります。

## 学習の進め方 (おすすめルート)

1. **触る** — 実験室でTODOを追加/完了/削除し、右のX-Rayパネルを眺める
2. **じっくりモードON** 🐢 — 「旅の地図」を1ステージずつナレーション付きで追う
3. **失敗させる** 💥 — 実験コーナーで 400 / 404 エラーの応答を観察する
4. **読む** 📖 — 教科書タブの第1〜10章で概念を体系的に整理する
5. **本物を覗く** — F12(開発者ツール)のNetworkタブで、X-Rayと同じ通信を確認する
6. **コードを読む** — `server.py` → `static/app.js` の順。全行に日本語コメント付き
7. **壊して直す** — 教科書第10章の改造課題に挑戦する

## ここで学べること

| 分類 | 内容 |
|------|------|
| 全体像 | クライアント/サーバーモデル、リクエストとレスポンスの往復 |
| HTTP | URL構造、メソッド(GET/POST/PATCH/DELETE)、ステータスコード(200/201/400/404/405/500)、ヘッダー、JSON |
| フロントエンド | HTML/CSS/JSの役割分担、DOM操作、fetch()による非同期通信、XSS対策の基本 |
| バックエンド | ルーティング、バリデーション、エラー設計、レスポンス生成 |
| データベース | SQLite、CRUDに対応する4つのSQL、プレースホルダーとSQLインジェクション対策、永続化 |

## ファイル構成

```text
├── DESIGN.md          # 設計書 (要件・アーキテクチャ・API/DB設計・図)

```

## テスト

```bash
cd learning-lab
python3 test_server.py         # 標準ライブラリの unittest で実行
# または (リポジトリの開発環境がある場合)
uv run pytest learning-lab/ -v
```

一時ディレクトリのDBを使うので、手元の `data/todos.db` は汚れません。
リポジトリ本体のCI(`tests/` のみ収集)からは独立しています。

## 学び終えたら — 発展課題

1. **検索機能**: `GET /api/todos?q=牛乳` — クエリ文字列と `WHERE title LIKE ?` を学ぶ
2. **期限カラムの追加**: `ALTER TABLE` と `ORDER BY` を学ぶ
3. **件数API**: `GET /api/todos/count` を自作 — ルーティング表に1行足すだけで作れる
4. **ユーザー認証**: Cookieとセッションの世界へ
5. **公開してみる**: HTTPS・ドメイン・ホスティングの世界へ
